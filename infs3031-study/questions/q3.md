## File 1: `support.jsp` — Input Form

```jsp
<%@ taglib prefix="s" uri="/struts-tags" %>
<html><body>
  <h1>Customer Support</h1>

  <%-- Posts to the action named "submitSupport" in struts.xml --%>
  <s:form action="submitSupport" method="post">
    <s:textfield name="email" label="Email Address"/>
    <s:textarea  name="issue" label="Describe Your Issue"/>
    <s:submit value="Submit"/>
  </s:form>

  <%-- Displays any error messages from the Action --%>
  <s:actionerror/>
</body></html>
```

- `<s:form action="submitSupport">` — on submit, Struts2 looks up `submitSupport` in `struts.xml`
- `name="email"` and `name="issue"` must match the property names in the Action class — Struts2 automatically calls the setters

## File 2: `SupportAction.java` — Action Class

```java
package com.support;

import com.opensymphony.xwork2.ActionSupport;

public class SupportAction extends ActionSupport {

    private String email;
    private String issue;

    // Getters and setters — Struts2 uses these to inject form values
    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }

    public String getIssue() { return issue; }
    public void setIssue(String issue) { this.issue = issue; }

    @Override
    public String execute() {

        // Basic validation
        if (email == null || email.trim().isEmpty()) {
            addActionError("Email is required.");
            return INPUT;   // sends user back to support.jsp
        }
        if (issue == null || issue.trim().isEmpty()) {
            addActionError("Issue is required.");
            return INPUT;
        }

        return SUCCESS;     // forwards to thankyou.jsp
    }
}
```

- `extends ActionSupport` — gives access to `SUCCESS`, `INPUT`, `ERROR` constants and `addActionError()`
- Struts2 calls `setEmail()` and `setIssue()` automatically before `execute()` runs
- `return SUCCESS` → Struts2 looks up the `"success"` result in `struts.xml` and forwards to `thankyou.jsp`
- `return INPUT` → sends the user back to the form with the error message displayed

## File 3: `thankyou.jsp` — Confirmation Page

```jsp
<%@ taglib prefix="s" uri="/struts-tags" %>
<html><body>
  <h1>Thank You!</h1>
  <p>Your support request has been received.</p>

  <%-- s:property reads values from the Action class via the ValueStack --%>
  <p><strong>Email:</strong> <s:property value="email"/></p>
  <p><strong>Issue:</strong> <s:property value="issue"/></p>
</body></html>
```

- `<s:property value="email"/>` — calls `getEmail()` on the Action object, which Struts2 puts on the ValueStack after `execute()` runs

## File 4: `struts.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE struts PUBLIC
  "-//Apache Software Foundation//DTD Struts Configuration 2.5//EN"
  "http://struts.apache.org/dtds/struts-2.5.dtd">

<struts>
  <package name="default" namespace="/" extends="struts-default">

    <action name="submitSupport" class="com.support.SupportAction">
      <result name="success">/thankyou.jsp</result>
      <result name="input">/support.jsp</result>
    </action>

  </package>
</struts>
```

- Maps the URL `/submitSupport` to `SupportAction`
- `"success"` → `thankyou.jsp`, `"input"` → back to `support.jsp`

## File 5: `web.xml`

```xml
<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee" version="3.1">

  <%-- Struts2 uses a Filter as its front controller, not a Servlet --%>
  <filter>
    <filter-name>struts2</filter-name>
    <filter-class>
      org.apache.struts2.dispatcher.filter.StrutsPrepareAndExecuteFilter
    </filter-class>
  </filter>

  <filter-mapping>
    <filter-name>struts2</filter-name>
    <url-pattern>/*</url-pattern>
  </filter-mapping>

  <welcome-file-list>
    <welcome-file>support.jsp</welcome-file>
  </welcome-file-list>

</web-app>
```

- `StrutsPrepareAndExecuteFilter` intercepts every request and routes it through Struts2
- `/*` means all URLs pass through the filter

## Deployment

1. Compile `SupportAction.java` with `struts2-core.jar` on the classpath
2. Place `SupportAction.class` in `WEB-INF/classes/com/support/`
3. Place `struts.xml` in `WEB-INF/classes/`
4. Place Struts2 JARs in `WEB-INF/lib/`
5. Copy `CustomerSupport/` into Tomcat's `webapps/` folder
6. Start Tomcat — visit `http://localhost:8080/CustomerSupport/support.jsp`

## Part B (5 marks) — Struts2 Request Lifecycle

```
1. Browser sends POST /submitSupport
2. StrutsPrepareAndExecuteFilter intercepts (declared in web.xml)
3. Struts2 checks struts.xml → finds "submitSupport" → SupportAction
4. Interceptor stack runs BEFORE execute():
   - Parameters interceptor calls setEmail(), setIssue() with form values
   - Validation interceptor runs
5. execute() runs → returns "success" or "input"
6. Struts2 looks up the result in struts.xml → forwards to the correct JSP
7. JSP renders — <s:property> reads values from the Action via ValueStack
8. HTTP response sent back to browser
```

| Component | Role |
|-----------|------|
| `StrutsPrepareAndExecuteFilter` | Front controller — intercepts every request |
| `struts.xml` | Maps URLs to Action classes and results to JSPs |
| **Interceptors** | Run before/after execute() — handle param injection, validation |
| **Action class** | Business logic — execute() returns a result name |
| **ValueStack** | Holds the Action object so JSPs can read its properties |
