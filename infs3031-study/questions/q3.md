# Question 3 (25 marks) — Struts2: Customer Support System

---

## Overview / Data Flow

```
Browser (support.jsp)
  → POST /submitSupport
    → FilterDispatcher (Struts2 front controller)
      → SupportAction.java (execute() reads email + issue)
        → struts.xml maps result "success" → thankyou.jsp
          → thankyou.jsp displays confirmation to user
```

## File 1: `support.jsp` — Input Form

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8" %>
<%@ taglib prefix="s" uri="/struts-tags" %>
<!DOCTYPE html>
<html>
<head><title>Customer Support</title></head>
<body>
  <h1>Customer Support</h1>

  <%-- s:form posts to the action named "submitSupport" in struts.xml --%>
  <s:form action="submitSupport" method="post">
    <s:textfield name="email" label="Email Address" required="true"/>
    <s:textarea  name="issue" label="Describe Your Issue" required="true"/>
    <s:submit value="Submit"/>
  </s:form>
</body>
</html>
```

**Explanation:**
- `<%@ taglib prefix="s" uri="/struts-tags" %>` — imports the Struts2 tag library
- `<s:form action="submitSupport">` — on submit, Struts2 intercepts the request and looks up `submitSupport` in `struts.xml`
- `<s:textfield name="email">` — the `name` attribute must match the property name in the Action class (Struts2 automatically injects the value via a setter)

## File 2: `SupportAction.java` — The Action Class

```java
package com.support;

import com.opensymphony.xwork2.ActionSupport;

// ActionSupport provides default execute(), input validation, and i18n helpers
public class SupportAction extends ActionSupport {

    // Properties must match the form field name= attributes
    private String email;
    private String issue;

    // --- Getters and Setters ---
    // Struts2 uses these to inject form values BEFORE execute() is called
    public String getEmail() { return email; }
    public void   setEmail(String email) { this.email = email; }

    public String getIssue() { return issue; }
    public void   setIssue(String issue) { this.issue = issue; }

    // execute() is the default method called by Struts2 when the action is invoked
    // It returns a String result name that struts.xml maps to a JSP
    @Override
    public String execute() {

        // Basic server-side validation
        if (email == null || email.trim().isEmpty()) {
            addActionError("Email is required.");
            return INPUT;   // "input" result → sends user back to support.jsp
        }
        if (issue == null || issue.trim().isEmpty()) {
            addActionError("Issue description is required.");
            return INPUT;
        }

        // Success — struts.xml will forward to thankyou.jsp
        return SUCCESS;  // SUCCESS is the constant "success" from ActionSupport
    }
}
```

**Explanation:**

| Code | What it does |
|------|-------------|
| `extends ActionSupport` | Inherits `SUCCESS`, `INPUT`, `ERROR` constants and validation helpers |
| `private String email` + getter/setter | Struts2's ValueStack automatically calls `setEmail()` with the posted form value |
| `execute()` returns `SUCCESS` | The string "success" — `struts.xml` maps this to `thankyou.jsp` |
| `return INPUT` | Sends the user back to the input form with error messages |
| `addActionError(...)` | Adds a global error; displayed in JSP with `<s:actionerror/>` |

## File 3: `thankyou.jsp` — Confirmation Page

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8" %>
<%@ taglib prefix="s" uri="/struts-tags" %>
<!DOCTYPE html>
<html>
<head><title>Thank You</title></head>
<body>
  <h1>Thank You!</h1>
  <p>Your support request has been received.</p>

  <%-- s:property reads values from the Action class via the ValueStack --%>
  <p><strong>Email:</strong> <s:property value="email"/></p>
  <p><strong>Your Issue:</strong> <s:property value="issue"/></p>

  <p>We will respond to <s:property value="email"/> within 24 hours.</p>
</body>
</html>
```

**Explanation:**
- `<s:property value="email"/>` — reads the `email` field from the Action class (via `getEmail()`) using Struts2's ValueStack. No scriptlet code needed — the Action object is on the stack after `execute()` runs.

## File 4: `struts.xml` — Action Configuration

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE struts PUBLIC
  "-//Apache Software Foundation//DTD Struts Configuration 2.5//EN"
  "http://struts.apache.org/dtds/struts-2.5.dtd">

<struts>
  <package name="default" namespace="/" extends="struts-default">

    <!-- Maps the URL /submitSupport to SupportAction.execute() -->
    <action name="submitSupport" class="com.support.SupportAction">

      <!-- If execute() returns "success" → forward to thankyou.jsp -->
      <result name="success">/thankyou.jsp</result>

      <!-- If execute() returns "input" → send back to support.jsp -->
      <result name="input">/support.jsp</result>

    </action>

  </package>
</struts>
```

**Explanation:**
- `extends="struts-default"` — inherits the default Struts2 interceptor stack (handles parameter injection, validation, etc.)
- `<action name="submitSupport">` — matches the URL `/submitSupport` (from the form's `action=` attribute)
- `<result name="success">` — when `execute()` returns `"success"`, Struts2 forwards to `thankyou.jsp`

## File 5: `web.xml` — Declares the Struts2 Filter

```xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee" version="3.1">

  <!-- Struts2 works as a servlet filter, not a servlet -->
  <filter>
    <filter-name>struts2</filter-name>
    <filter-class>
      org.apache.struts2.dispatcher.filter.StrutsPrepareAndExecuteFilter
    </filter-class>
  </filter>

  <!-- Intercept ALL requests and pass them through Struts2 -->
  <filter-mapping>
    <filter-name>struts2</filter-name>
    <url-pattern>/*</url-pattern>
  </filter-mapping>

  <welcome-file-list>
    <welcome-file>support.jsp</welcome-file>
  </welcome-file-list>

</web-app>
```

**Explanation:**
- Struts2 uses a **Filter** (not a Servlet) as its entry point — `StrutsPrepareAndExecuteFilter`
- `<url-pattern>/*</url-pattern>` — every request goes through Struts2, which checks `struts.xml` to decide what to do

## Deployment Process

1. **Compile** `SupportAction.java` with `struts2-core.jar` on the classpath:
   ```bash
   javac -cp WEB-INF/lib/struts2-core-x.x.jar src/com/support/SupportAction.java -d WEB-INF/classes
   ```
2. **Place compiled class** at `WEB-INF/classes/com/support/SupportAction.class`
3. **Place Struts2 JARs** in `WEB-INF/lib/` (struts2-core, xwork-core, ognl, etc.)
4. **Place** `struts.xml` in `WEB-INF/classes/` (Struts2 looks for it on the classpath)
5. **Deploy** the `CustomerSupport/` folder to Tomcat's `webapps/` directory
6. **Start Tomcat** and visit `http://localhost:8080/CustomerSupport/support.jsp`

## Part B (5 marks) — Struts2 Request Lifecycle

```
1. Browser sends HTTP request (e.g. POST /submitSupport)
        ↓
2. StrutsPrepareAndExecuteFilter intercepts the request (declared in web.xml)
        ↓
3. Struts2 looks up the action name in struts.xml → finds "submitSupport" → SupportAction
        ↓
4. Interceptor stack runs BEFORE execute()
   - Parameters interceptor reads form fields and calls setEmail(), setIssue()
   - Validation interceptor runs any validation rules
   - Other interceptors (logging, i18n, etc.) also run here
        ↓
5. Action's execute() method is called
   - Business logic runs
   - Returns a result String (e.g. "success")
        ↓
6. Interceptor stack runs AFTER execute() (in reverse order)
        ↓
7. Struts2 looks up the result name in struts.xml
   - "success" → forwards to thankyou.jsp
        ↓
8. JSP renders — <s:property> reads values from Action via ValueStack
        ↓
9. HTTP response sent back to browser
```

### Key Components Summary

| Component | Role |
|-----------|------|
| `StrutsPrepareAndExecuteFilter` | Front controller — intercepts every request |
| `struts.xml` | Configuration — maps URLs to Action classes and results to JSPs |
| **Interceptors** | Pre/post processing (param injection, validation, logging) — run around execute() |
| **Action class** | Business logic — `execute()` returns a result name |
| **ValueStack** | Shared data store — the Action object is pushed here so JSPs can read its properties |
| **Result / JSP** | Presentation — renders the response using values from the ValueStack |
