## Part A (5 marks) — Main HTTP Request Methods

| Method | Purpose | Data location |
|--------|---------|---------------|
| **GET** | Retrieve a resource | URL query string (`?name=value`) |
| **POST** | Submit data to be processed | Request body (not visible in URL) |
| **PUT** | Replace a resource entirely | Request body |
| **DELETE** | Remove a resource | URL |
| **PATCH** | Partially update a resource | Request body |

**GET vs POST** — the most important distinction:
- **GET** — data is in the URL, bookmarkable, used for reading. Should never change server state.
- **POST** — data is in the request body, used for forms/login/creating records. Submitting twice creates two records.
- **PUT/DELETE/PATCH** — used in REST APIs to update and remove resources.

## Part B (10 marks) — Struts2 Tag Libraries in JSP

Tag libraries replace Java scriptlet code (`<% %>`) with cleaner XML-style tags. Struts2 provides its own tag library imported with `<%@ taglib prefix="s" uri="/struts-tags" %>`.

### Example: Displaying a list of support tickets

#### SupportListAction.java

```java
package com.support;

import com.opensymphony.xwork2.ActionSupport;
import java.util.ArrayList;
import java.util.List;

public class SupportListAction extends ActionSupport {

    private List<String> tickets;

    @Override
    public String execute() {
        // Populate the list — in a real app this would come from a database
        tickets = new ArrayList<>();
        tickets.add("Cannot log in to account");
        tickets.add("Payment not processing");
        tickets.add("Page not loading on mobile");
        return SUCCESS;
    }

    // Struts2 calls getTickets() to put the list on the ValueStack for the JSP
    public List<String> getTickets() { return tickets; }
}
```

#### ticketlist.jsp

```jsp
<%@ taglib prefix="s" uri="/struts-tags" %>
<html><body>
  <h1>Open Support Tickets</h1>

  <%-- s:if checks a condition using the ValueStack --%>
  <s:if test="tickets.isEmpty()">
    <p>No tickets found.</p>
  </s:if>
  <s:else>
    <ul>
      <%-- s:iterator loops over the tickets list from the Action --%>
      <s:iterator value="tickets" var="ticket">
        <%-- s:property prints the current loop variable --%>
        <li><s:property value="#ticket"/></li>
      </s:iterator>
    </ul>
  </s:else>

</body></html>
```

### Tag Explanation

| Tag | What it does |
|-----|-------------|
| `<%@ taglib prefix="s" uri="/struts-tags" %>` | Imports the Struts2 tag library — needed once per JSP |
| `<s:if test="...">` | Conditional block — evaluates an expression against the ValueStack |
| `<s:else>` | Runs when the `<s:if>` condition is false |
| `<s:iterator value="tickets" var="ticket">` | Loops over the `tickets` list from the Action |
| `<s:property value="#ticket"/>` | Prints the current item from the iterator |

**Why use tag libraries instead of scriptlets?**
- No Java code mixed into HTML — cleaner and easier to read
- Less error-prone — no missing semicolons inside JSP

## Part C (10 marks) — Session State in Struts2

### Why do we need session state?

HTTP is **stateless** — the server has no memory between requests. Without session state the server cannot tell who is logged in, what is in a shopping cart, or what page a user was on. Session state stores data on the server tied to a specific user across multiple requests.

---

### Example: Remembering the user's email after form submission

#### SupportAction.java — writes to session

```java
package com.support;

import com.opensymphony.xwork2.ActionSupport;
import org.apache.struts2.interceptor.SessionAware;
import java.util.Map;

public class SupportAction extends ActionSupport implements SessionAware {

    private String email;
    private String issue;
    private Map<String, Object> session;

    // Struts2 injects the session map via SessionAware
    @Override
    public void setSession(Map<String, Object> session) {
        this.session = session;
    }

    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
    public String getIssue() { return issue; }
    public void setIssue(String issue) { this.issue = issue; }

    @Override
    public String execute() {
        if (email == null || email.trim().isEmpty()) {
            addActionError("Email is required.");
            return INPUT;
        }

        // Save email to session — persists across future requests
        session.put("userEmail", email);

        return SUCCESS;
    }
}
```

- `implements SessionAware` — Struts2 injects the session map before `execute()` runs
- `session.put("userEmail", email)` — stores the value; available on every future request for this user

#### thankyou.jsp — reads from session

```jsp
<%@ taglib prefix="s" uri="/struts-tags" %>
<html><body>
  <h1>Thank You!</h1>

  <%-- From the Action (ValueStack) — only available this request --%>
  <p><strong>Email:</strong> <s:property value="email"/></p>
  <p><strong>Issue:</strong> <s:property value="issue"/></p>

  <%-- From the session — persists across requests --%>
  <p>Saved session email: <s:property value="#session.userEmail"/></p>
</body></html>
```

- `<s:property value="email"/>` — reads from the Action (current request only)
- `<s:property value="#session.userEmail"/>` — reads from the session (`#session` is Struts2's shortcut to the session map)

### ValueStack vs Session

| | ValueStack | Session |
|-|------------|---------|
| Scope | Current request only | Across all requests |
| Use for | Displaying submitted data | Logged-in user, cart, preferences |
