### File 1: `checkin.html` — Input Form

```html
<html>
<body>
  <form action="checkin" method="POST">
    <label>Full Name: <input type="text" name="fullName"></label><br>
    <label>Date of Birth: <input type="date" name="dob"></label><br>
    <label>Reason for Visit: <textarea name="reason"></textarea></label><br>
    <input type="submit" value="Check In">
  </form>
</body>
</html>
```

- `action="checkin"` — maps to the servlet URL pattern `/checkin` in `web.xml`
- `method="POST"` — form data sent in request body, not the URL
- `name` attributes on inputs are how the servlet reads the values

---

### File 2: `CheckInServlet.java` — The Servlet

```java
import java.io.*;
import javax.servlet.*;
import javax.servlet.http.*;

public class CheckInServlet extends HttpServlet {

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {

        // Read form values using the name= attributes from the HTML
        String fullName = request.getParameter("fullName");
        String dob      = request.getParameter("dob");
        String reason   = request.getParameter("reason");

        // Tell the browser we are sending back HTML
        response.setContentType("text/html");

        // Get a writer to send the response
        PrintWriter out = response.getWriter();

        // Write the confirmation page back to the browser
        out.println("<html><body>");
        out.println("<h1>Check-In Confirmed</h1>");
        out.println("<p>Name: " + fullName + "</p>");
        out.println("<p>Date of Birth: " + dob + "</p>");
        out.println("<p>Reason: " + reason + "</p>");
        out.println("</body></html>");
    }
}
```

**Explanation:**

| Code | What it does |
|------|-------------|
| `extends HttpServlet` | Inherits servlet behaviour from the Java EE API |
| `doPost(...)` | Called automatically when a POST request arrives at the mapped URL |
| `request.getParameter("fullName")` | Reads the submitted form field with `name="fullName"` |
| `response.setContentType("text/html")` | Tells the browser to render the response as HTML |
| `response.getWriter()` | Returns a stream to write the response back to the browser |

---

### File 3: `web.xml` — Maps the URL to the Servlet

```xml
<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee" version="3.1">

  <servlet>
    <servlet-name>CheckInServlet</servlet-name>
    <servlet-class>CheckInServlet</servlet-class>
  </servlet>

  <servlet-mapping>
    <servlet-name>CheckInServlet</servlet-name>
    <url-pattern>/checkin</url-pattern>
  </servlet-mapping>

</web-app>
```

- `<servlet>` declares the servlet class
- `<servlet-mapping>` links the URL `/checkin` to that class — so when the form posts to `checkin`, Tomcat knows to call `CheckInServlet`

---

### Deployment

1. Compile the servlet:
   ```bash
   javac -cp /path/to/tomcat/lib/servlet-api.jar CheckInServlet.java
   ```
2. Place `CheckInServlet.class` in `WEB-INF/classes/`
3. Place `web.xml` in `WEB-INF/`
4. Place `checkin.html` in the root of the app folder
5. Copy `HospitalApp/` into Tomcat's `webapps/` directory
6. Start Tomcat — visit `http://localhost:8080/HospitalApp/checkin.html`

## Part B (5 marks) — What does web.xml do?

`web.xml` is the **deployment descriptor** — an XML file at `WEB-INF/web.xml` that Tomcat reads at startup to configure the application.

**1. Servlet declaration and URL mapping** — the most important role:
```xml
<servlet>
  <servlet-name>CheckInServlet</servlet-name>
  <servlet-class>CheckInServlet</servlet-class>
</servlet>
<servlet-mapping>
  <servlet-name>CheckInServlet</servlet-name>
  <url-pattern>/checkin</url-pattern>
</servlet-mapping>
```

**2. Welcome page** — which file loads when the user visits `/`:
```xml
<welcome-file-list>
  <welcome-file>checkin.html</welcome-file>
</welcome-file-list>
```

**3. Session timeout** — how long before an idle session expires (minutes):
```xml
<session-config>
  <session-timeout>30</session-timeout>
</session-config>
```

**4. Error pages** — redirect to a custom page on HTTP errors:
```xml
<error-page>
  <error-code>404</error-code>
  <location>/error404.html</location>
</error-page>
```

Without `web.xml`, Tomcat does not know which servlet class handles which URL.
