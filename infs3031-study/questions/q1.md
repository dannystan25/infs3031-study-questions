# Question 1 (25 marks) — Java Servlets, Form Handling & Deployment

---

## Part A (20 marks) — Hospital Patient Check-In Servlet

### Overview / Data Flow

```
Browser (HTML form)
  → POST /checkin
    → CheckInServlet.java (reads params, builds response)
      → confirmation HTML sent back to browser
```

---

### File 1: `checkin.html` — The HTML Form

```html
<!DOCTYPE html>
<html>
<head><title>Patient Check-In</title></head>
<body>
  <h1>Hospital Patient Check-In</h1>
  <form action="checkin" method="POST">
    <label>Full Name: <input type="text" name="fullName" required></label><br>
    <label>Date of Birth: <input type="date" name="dob" required></label><br>
    <label>Reason for Visit: <textarea name="reason" required></textarea></label><br>
    <input type="submit" value="Check In">
  </form>
</body>
</html>
```

**Key points:**
- `action="checkin"` — maps to the servlet URL pattern `/checkin`
- `method="POST"` — form data is sent in the request body (not the URL)
- `name` attributes on inputs are what the servlet uses to read the values

---

### File 2: `CheckInServlet.java` — The Servlet

```java
import java.io.*;
import javax.servlet.*;
import javax.servlet.http.*;

public class CheckInServlet extends HttpServlet {

    // doGet() handles GET requests (e.g. typing the URL directly)
    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        // Redirect to the form if someone visits /checkin directly
        response.sendRedirect("checkin.html");
    }

    // doPost() handles the form submission
    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {

        // 1. Read the submitted form data using the input name attributes
        String fullName = request.getParameter("fullName");
        String dob      = request.getParameter("dob");
        String reason   = request.getParameter("reason");

        // 2. Basic server-side validation
        if (fullName == null || fullName.trim().isEmpty()) {
            response.sendError(HttpServletResponse.SC_BAD_REQUEST, "Full name is required.");
            return;
        }

        // 3. Set the response content type so the browser renders HTML
        response.setContentType("text/html");
        response.setCharacterEncoding("UTF-8");

        // 4. Get a PrintWriter to write HTML back to the browser
        PrintWriter out = response.getWriter();

        // 5. Write the confirmation page
        out.println("<!DOCTYPE html>");
        out.println("<html><head><title>Check-In Confirmation</title></head><body>");
        out.println("<h1>Check-In Confirmed</h1>");
        out.println("<p><strong>Name:</strong> " + fullName + "</p>");
        out.println("<p><strong>Date of Birth:</strong> " + dob + "</p>");
        out.println("<p><strong>Reason for Visit:</strong> " + reason + "</p>");
        out.println("<p>Please take a seat. A nurse will be with you shortly.</p>");
        out.println("</body></html>");
    }
}
```

**Line-by-line explanation:**

| Code | What it does |
|------|-------------|
| `extends HttpServlet` | Inherits servlet lifecycle methods from the Java EE API |
| `doPost(...)` | Called automatically by the servlet container when a POST request arrives at the mapped URL |
| `request.getParameter("fullName")` | Reads the value of the form field whose `name="fullName"` |
| `response.setContentType("text/html")` | Tells the browser how to interpret the response |
| `response.getWriter()` | Returns a stream to write the response body |

### File 3: `web.xml` — Deployment Descriptor (maps URL → Servlet)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee" version="3.1">

  <!-- Declare the servlet class -->
  <servlet>
    <servlet-name>CheckInServlet</servlet-name>
    <servlet-class>CheckInServlet</servlet-class>
  </servlet>

  <!-- Map a URL pattern to the servlet -->
  <servlet-mapping>
    <servlet-name>CheckInServlet</servlet-name>
    <url-pattern>/checkin</url-pattern>
  </servlet-mapping>

</web-app>
```

### Deployment Process & File Locations

The project must follow the standard **WAR (Web Application Archive)** directory structure:

```
HospitalApp/
├── checkin.html                        ← served directly by the web server
└── WEB-INF/
    ├── web.xml                         ← deployment descriptor
    ├── classes/
    │   └── CheckInServlet.class        ← compiled .class file goes here
    └── lib/                            ← any JAR dependencies go here
```

**Step-by-step deployment:**

1. **Write the code** — create `CheckInServlet.java` and `checkin.html`
2. **Compile the servlet:**
   ```bash
   javac -cp /path/to/tomcat/lib/servlet-api.jar CheckInServlet.java
   ```
   The `servlet-api.jar` provides the `HttpServlet`, `HttpServletRequest`, etc. classes.
3. **Place** the `.class` file in `WEB-INF/classes/`
4. **Place** `web.xml` in `WEB-INF/`
5. **Place** `checkin.html` in the root of the web app folder
6. **Deploy to Tomcat** — copy the `HospitalApp/` folder into Tomcat's `webapps/` directory
7. **Start Tomcat** — `bin/startup.sh` (Linux) or `bin/startup.bat` (Windows)
8. **Access the app** at `http://localhost:8080/HospitalApp/checkin.html`

## Part B (5 marks) — What does web.xml do?

`web.xml` is the **deployment descriptor** for a Java web application. It is an XML configuration file located at `WEB-INF/web.xml`. The servlet container (e.g. Tomcat) reads it at startup to configure the application.

### Key things web.xml does:

**1. Servlet declaration and URL mapping** — tells the container which class handles which URL:
```xml
<servlet>
  <servlet-name>CheckInServlet</servlet-name>
  <servlet-class>CheckInServlet</servlet-class>
</servlet>
<servlet-mapping>
  <servlet-name>CheckInServlet</servlet-name>
  <url-pattern>/checkin</url-pattern>
</servlet-mapping>
```

**2. Setting the welcome/default page** — which file loads when the user visits `/`:
```xml
<welcome-file-list>
  <welcome-file>checkin.html</welcome-file>
</welcome-file-list>
```

**3. Configuring init parameters** — pass configuration values to a servlet without hardcoding:
```xml
<context-param>
  <param-name>adminEmail</param-name>
  <param-value>admin@hospital.com</param-value>
</context-param>
```

**4. Configuring error pages** — handle HTTP errors gracefully:
```xml
<error-page>
  <error-code>404</error-code>
  <location>/error404.html</location>
</error-page>
```

**5. Session timeout** — set how long before an idle session expires (in minutes):
```xml
<session-config>
  <session-timeout>30</session-timeout>
</session-config>
```

### Summary
Without `web.xml`, the servlet container does not know which servlet class to use for a given URL. It is the glue between URLs and Java classes. (Note: since Servlet 3.0 you can replace `web.xml` mappings with the `@WebServlet` annotation, but `web.xml` is still widely used and tested in exams.)
